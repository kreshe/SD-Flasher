# SD FLASHER

**SD FLASHER** — графическая утилита для Ubuntu/Linux для одновременной записи одного образа на несколько SD-карт и USB-накопителей.

Проект рассчитан на сервисные и тестовые станции, где один и тот же образ нужно быстро записывать сразу на несколько накопителей, например через несколько USB-кардридеров.

## Возможности

- 🖥️ Современный тёмный GUI на Tkinter.
- 💾 Выбор одного образа для записи.
- 🔁 Параллельная запись одного образа сразу на несколько накопителей.
- ✅ Выбор целей через чекбоксы.
- 🔍 Автоматическое обнаружение съёмных SD/USB-устройств через `lsblk` + `udevadm`.
- 🛡️ Системный диск автоматически исключается из списка целей.
- 🔒 Устройства только для чтения нельзя выбрать для записи.
- ⏏️ Перед прошивкой разделы выбранных устройств автоматически размонтируются.
- 📊 Живой прогресс, скорость, объём записанных данных и время для каждой карты.
- 📜 **LIVE LOG** для каждого параллельного задания прямо в интерфейсе.
- 📝 Отдельный лог-файл для каждого устройства.
- 🔄 Выполнение `sync` после успешной записи.
- 💽 Повторная прошивка уже записанных карт поддерживается — наличие старой разметки или файлов не мешает выбору устройства.
- 🧭 Кардридеры Transcend `TS-RDF5A` распознаются отдельно, если соответствующая информация доступна через USB/udev.
- 📁 Собственное окно выбора образа вместо системного `filedialog`.
- 💾 Последний выбранный образ запоминается между запусками.

## Поддерживаемые образы

Поддерживаются:

- `.img`
- `.img.xz`
- `.img.gz`
- `.img.zst`

Сжатые образы распаковываются на лету и сразу передаются в `dd`, без необходимости предварительно распаковывать их вручную.

## Как работает запись

Каждый выбранный накопитель получает отдельный процесс записи. Поэтому при выборе, например, трёх карт:

```text
/dev/sdb  ──┐
/dev/sdc  ──┼──> один и тот же образ записывается одновременно
/dev/sdd  ──┘
```

Для обычного `.img` используется:

```bash
dd if=IMAGE of=/dev/sdX bs=16M iflag=fullblock status=progress conv=fsync
```

Для сжатых образов используется потоковая распаковка:

```text
IMAGE.xz  →  xz -dc   →  dd  →  /dev/sdX
IMAGE.gz  →  gzip -dc →  dd  →  /dev/sdX
IMAGE.zst →  zstd -dc →  dd  →  /dev/sdX
```

После успешной записи выполняется:

```bash
sudo sync
```

## Требования

Проект предназначен для Linux с графической сессией, в первую очередь для Ubuntu.

Нужны:

- Bash
- Python 3
- `python3-tk`
- `sudo`
- `lsblk`
- `findmnt`
- `udevadm`
- `dd`
- `umount`
- `sync`
- `blockdev`

Для сжатых образов дополнительно:

- `xz` для `.xz`
- `gzip` для `.gz`
- `zstd` для `.zst`

На Ubuntu основные зависимости можно установить так:

```bash
sudo apt update
sudo apt install -y python3 python3-tk util-linux coreutils sudo xz-utils gzip zstd
```

## Установка

Скачайте `sd_flasher.sh` и сделайте его исполняемым:

```bash
chmod +x sd_flasher.sh
```

После этого запускайте:

```bash
./sd_flasher.sh
```

Скрипт должен запускаться из графической Linux-сессии.

## Выбор образа

Нажатие **«ВЫБРАТЬ ОБРАЗ»** открывает собственный файловый менеджер проекта.

В нём доступны:

- переход по каталогам;
- `Домой`, `Загрузки`, `Музыка`, `Документы` и `/`;
- строка пути;
- поиск по имени;
- показ скрытых файлов;
- фильтр образов;
- просмотр размера файла;
- двойной клик для выбора образа.

Последний выбранный путь сохраняется в:

```text
~/.sd_flasher.conf
```

При следующем запуске его можно использовать повторно без повторной навигации по каталогам.

## Выбор SD-карт

После выбора образа утилита показывает найденные внешние накопители.

Пример:

```text
/dev/sdb    59.5G    usb    Transcend TS-RDF5A · кардридер
/dev/sdc    59.5G    usb    Transcend
/dev/sdd    32.0G    usb    Kingston
```

Статусы могут показываться как:

```text
ГОТОВ
СМОНТИРОВАН
ТОЛЬКО ЧТЕНИЕ
```

**Смонтированные карты не исключаются из списка.** Это важно для повторной прошивки уже использованных SD-карт. Перед записью их разделы автоматически размонтируются.

## Защита системного диска

Утилита определяет диск, на котором находится корневая файловая система `/`, и исключает его из списка целей.

Например, если система установлена на:

```text
/dev/sda
```

то `/dev/sda` не должен появиться как доступная цель записи.

Несмотря на защиту, перед любой записью всегда внимательно проверяйте выбранные устройства: запись на блочное устройство полностью уничтожает его текущее содержимое.

## Интерфейс во время записи

Для каждой карты создаётся отдельная карточка:

```text
/dev/sdb                     ЗАПИСЬ
██████████████░░░░░░░░       62%

Записано: 11.2 GiB
Скорость: 93 MB/s
Время:    00:41

LIVE LOG
────────────────────────────────────
11.0 GiB copied, 40 s, 92.8 MB/s
11.2 GiB copied, 41 s, 93.1 MB/s
```

Таким образом, при одновременной записи нескольких карт видно состояние каждой отдельной операции.

## Логи

Логи сохраняются в:

```text
~/.sd_flasher_logs/
```

Для каждого устройства создаётся отдельный файл, например:

```text
~/.sd_flasher_logs/sdb_20261001_125304_147860_1.log
~/.sd_flasher_logs/sdc_20261001_125304_147860_2.log
```

В логах сохраняются:

- устройство;
- образ;
- время начала;
- сообщения `dd`;
- скорость и объём записи;
- ошибки;
- результат `sync`.

## Остановка записи

Кнопка **«Остановить»** отправляет активным операциям сигнал остановки.

После принудительной остановки карта может содержать неполный образ и стать нечитаемой. В таком случае её необходимо прошить заново.

## Рабочий сценарий

Типичный сценарий выглядит так:

```text
1. Запустить sd_flasher.sh
2. Нажать «ВЫБРАТЬ ОБРАЗ»
3. Выбрать .img / .img.xz / .img.gz / .img.zst
4. Отметить нужные SD-карты
5. Нажать «НАЧАТЬ ПАРАЛЛЕЛЬНУЮ ЗАПИСЬ»
6. Подтвердить предупреждение
7. Наблюдать прогресс и LIVE LOG каждой карты
8. Дождаться статуса «ГОТОВО»
```

## Структура пользовательских данных

```text
~/.sd_flasher.conf
~/.sd_flasher_logs/
```

## Безопасность

Утилита работает с блочными устройствами и использует `sudo` для операций записи и размонтирования.

**Все данные выбранных накопителей будут уничтожены.**

Никогда не выбирайте устройство, на котором находятся нужные данные.

Перед началом записи рекомендуется проверить размер и модель каждой выбранной карты.

## Ограничения

- GUI требует графическую Linux-сессию.
- Для запуска нужен `python3-tk`.
- Для записи используются права `sudo`.
- Для сжатых форматов соответствующий распаковщик должен быть установлен.
- Для очень больших образов время записи зависит от реальной скорости кардридера, SD-карты и USB-порта.
